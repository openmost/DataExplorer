# Final fix wave: complete findings list (backend from the final review + UI changes requested by Ronan)

## A. Backend (final whole-branch review, Important)
A1. Any edit wipes a visual report's history. Dao/ReportsDao.php:109 bumps `revision` on every update; RecordBuilders/SavedReport.php:317-320 builds the record name from it; API.php:322-325 invalidates 6 months of every DataExplorer report on the placed sites. Fix: bump revision and invalidate only when a computed field changes (technique, report_type, rows, column, metrics, filters, segment, type, sql); on placement change without computed change, invalidate only the ADDED sites (no revision bump). Rename / reorder / category or subcategory change: no bump, no invalidation. Replace ManagementApiTest::test_update_..._andBumpsTheRevision accordingly and add "rename keeps data" (archived record still readable after rename) and "added site gets invalidated, kept sites not".
A2. Scheduled email reports / API.getProcessedReport render DataExplorer reports wrongly: Reports/GetSavedReport.php:83-101 never resets `$processedMetrics` so core defaults (nb_actions_per_visit, avg_time_on_site, bounce_rate, conversion_rate) are added as zero columns (plugins/API/ProcessedReport.php:564-583, 765-784), pivot columns are dropped, SQL reports come out empty. Fix: `$this->processedMetrics = []`; declare pivot columns in metrics metadata when knowable (from the definition and archived columns), and for SQL reports declare the result columns (from the last cached result or by declaring a generic metric list derived at init; if not reliably knowable, mark SQL reports as not supported in scheduled reports: exclude them from ScheduledReports report lists via the core event, and adjust README/CHANGELOG claims). Add one API.getProcessedReport integration test per kind: visual table with pivot, evolution, KPI, SQL table.
A3. Anonymous users with view access get a live query engine: Access/ReportPermissions.php:23-26 checkCanExplore only needs view. Fix: `Piwik::checkUserIsNotAnonymous()` in checkCanExplore (runVisual, getCatalog, getCategories as relevant); for anonymous viewers of saved SQL reports serve cache-only (no live query on cache miss: return an empty table with a translated "data not available yet" message, or refuse): your call, document, test with the real anonymous user (FakeAccess / Piwik::isUserIsAnonymous), rename the misnamed test.
A4. 3-dimension reports hit placeholder/packet limits: Query/VisualQueryRunner.php:261-269/292/334 with VisualQueryBuilder.php:284 tuplePredicate build include/exclude IN lists sized by kept parents (up to 50,000 tuples at level 2 with default caps): MYSQLI native prepares fail past 65,535 placeholders (archive fails on every run since DB errors propagate), PDO builds MB-long SQL (max_allowed_packet). Fix: restrict child levels by joining on / filtering through the parent level's kept labels without one placeholder per value (e.g. chunk the lists into batches of at most 1,000 tuples per statement and merge, or materialize kept parents in a temporary table on the same connection and JOIN): pick the simplest correct approach, keep per-parent ranking semantics and Others exact; add a test that forces chunking with a small configured chunk size.
